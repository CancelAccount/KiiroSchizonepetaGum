# 1. 特效着色器迁移到 1.7 原生管线

> [← 返回总览](00-总览.md)
> **来源**：2026-10-22 用户「环世界更新了 1.7，使用了 shader 的 mod 无法兼容」「只做第 1 层，先创建技术文档」
> **口径**：**已实施**：对象级特效统一走 `ShaderDef` + GLSL 450 + `Graphics.DrawMesh`，2026-10-23 实机验收通过（[§1.6](#16-决策表)）
> **范围**：`KiiroSchizonepetaGum` 1.7 分支；描边为首个使用者；不含全屏后处理与屏幕空间特效
> **关联**：1.6 的实现细节与"为什么是片元邻域膨胀"的选型论证见 [Outline_技术方案.md](Outline_技术方案.md)，本篇只记 1.7 增量

## 1.1 诉求与现象

| 场景 | 现状（1.7） | 期望 |
|---|---|---|
| 游戏内描边 | 完全不可见，控制台提示 shader 不可用 | 与 1.6 一致的描边效果 |
| shader 交付形态 | Unity AssetBundle（`AssetBundles/kiirogum_win`） | GLSL 源码随 mod 直接加载，无 AB |
| 平台覆盖 | 仅 Windows 有特效（平台后缀匹配 AB） | 全平台一致 |
| 后续调参 | 每次改 shader 都要开 Unity 重打 AB | 改 `.glsl` 后重启游戏即生效 |

## 1.2 机制

1.7 渲染栈已换成自研引擎 Waylith（Vulkan 后端），`UnityEngine.*` 仅由 `UnityStubs.dll` 提供兼容壳。

- **AB 里的 Unity shader 不可用**：`UnityShaderAsset.Read` 只接受 `PlatformVulkan = 18` 变体；缺失时回退读「相邻 Linux bundle」，再失败即 `Shader.Unsupported`（Windows 构建的 bundle 两者都没有）。
- **mod 着色器改为源码交付**：`ShaderDefRegistry.RegisterShaderDirectories()` 扫描每个加载目录下名为 `Shaders` 的文件夹，把其中 `.glsl` 交给 `ShaderSourceLoader` 编译；同名文件时 mod 目录优先于 Core。
- **ShaderTypeDef 仍然可用**：`TryLoadShader` 取 `shaderPath` 最后一段，若存在同名 `ShaderDef` 则跳过 AB，走 `CreateLateBound` → `ShaderRegistry` 延迟解析。
- **材质契约不变**：uniform 写进 `layout(set = 2, binding = 0) uniform MaterialUniforms`（std140，≤512 字节），主贴图固定 `_MainTex`（`binding = 1`），`MaterialPropertyBlock` 按名覆盖。

```xml
<!-- ShaderDef 只需描述渲染状态；顶点着色器默认用引擎的 SceneDefault.vert.glsl -->
<ShaderDef>
  <defName>KiiroGumOutline</defName>
  <shaderProgram>
    <fragmentShaderFileName>KiiroGumOutline.frag.glsl</fragmentShaderFileName>
    <transparent>true</transparent>
    <depthWrite>false</depthWrite>
    <cullMode>None</cullMode>
    <!-- 2901 = 排在 Cutout/CutoutPlant（2900，写深度）之后，详见 03 D8 -->
    <renderQueue>2901</renderQueue>
  </shaderProgram>
</ShaderDef>
```

```glsl
// 关键约定：uniform 成员名即 MaterialPropertyBlock 的键；_ST 后缀由引擎按贴图变换自动填充
layout(set = 2, binding = 0) uniform MaterialUniforms
{
    vec4  _OutlineColor;  // @color @default = vec4(0.4, 0.8, 0.2, 1.0)
    vec4  _MainTex_ST;    // @default = vec4(0.0, 0.0, 1.0, 1.0)
    vec4  _FrameUV;       // @default = vec4(0.0, 0.0, 1.0, 1.0)
    float _OutlineWidth;  // @default = 2.0
} u;
layout(set = 2, binding = 1) uniform sampler2D _MainTex;
```

## 1.3 现状排查

| 对象 | 1.7 状态 | 处置 |
|---|---|---|
| `1.6/AssetBundles/kiirogum_win` | 加载到但 shader 变 `Unsupported` | 1.7 不使用，1.6 保留 |
| `1.6/Defs/ShaderTypeDefs/KiiroGum_Outline.xml` | 有效，但 `shaderPath` 找不到同名 `ShaderDef` 时仍走 AB | 1.7 补同名 `ShaderDef` |
| `UnityProject/.../KiiroGumOutline.shader` | 仅 1.6 有效 | 改写为 GLSL 450 |
| `KiiroGumOutlineManager.OutlineShader` | 取 `ShaderTypeDef.Shader`，失败回退默认 shader | 改取 `ShaderDef.Shader` |
| `KiiroGumOutlineManager.IsOutlineSupported` | 基于 `Application.platform` 的 Windows 判定 | 1.7 删除（无平台差异） |

同坑面：贴图、声音、材质等 AB 资源在 1.7 仍可按原方式加载，**只有 shader 必须走源码管线**。

已排除项（逐项对照 1.7 反编译，均未变）：`GlobalTextureAtlasManager.TryGetPawnFrameSet`、`PawnCacheRenderer.RenderPawn`、`PawnRenderUtility.AltitudeForLayer`、`MaterialPool.MatFrom(MaterialRequest)`、`GenDraw.DrawMeshNowOrLater`、`MaterialPropertyBlock`；站立 `bodyAngle` 仍恒为 0（描边层继续用 identity 矩阵）。

## 1.4 候选做法

| 做法 | 落点 | 覆盖 | 副作用 | 结论 |
|---|---|---|---|---|
| GLSL 450 + `ShaderDef` | `1.7/Shaders/*.glsl` + `1.7/Defs/ShaderDefs/*.xml` | 对象级特效全部 | 需重写 shader；改后需重启 | ✅ 采用 |
| 补 `kiirogum_linux` AB | `1.7/AssetBundles/` | 保住旧 shader | 依赖引擎未公开回退；需 Unity Linux 构建 | 不实施（只作应急备忘） |
| 自定义 render pass（`IRenderFeature`） | `FrameRenderer.AddFeature` + `IRenderPass.Record` | 全屏/跨物体 | 非 RimWorld 使用面，随小版本易碎 | 不实施（无需求） |
| 裸 Vulkan（自建 device/pipeline） | P/Invoke `vulkan-1.dll` | 无 | 与引擎帧同步冲突，画不进游戏画面 | 不实施（不可行） |
| 复用官方描边类 shader | `RitualOutline` / `PawnSilhouetteStencil` | 固定样式 | 无法按玩家设置调色/调宽 | 不实施 |

## 1.5 影响面与副作用

| 维度 | 结论 |
|---|---|
| 兼容性 | 1.7 专用；1.6 分支与其 AB 管线不动，互不影响 |
| 迁移 | 需要新增 `1.7/` 目录与 csproj；C# 只改 shader 获取与平台判定两处 |
| 依赖 | 无新外部依赖；不再需要 Unity 工程打 AB |
| 展示 | 效果与 1.6 一致；UV 朝向需实机确认 |
| 性能 | 与 1.6 同构：每目标每帧一次 DrawMesh，逐像素开销在 GPU |
| 回滚 | 删 `1.7/Shaders` 与 `ShaderDef` 即回到"描边停用"，不影响本体渲染 |
