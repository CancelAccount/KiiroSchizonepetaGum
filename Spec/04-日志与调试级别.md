# 4. 日志与调试级别

> [← 返回总览](00-总览.md)
> **来源**：2026-10 用户「本mod日志封装类名用KiiroGumLog」「把调试日志级别放入debug级，添加初始化日志，输出其包类型」「日志相关放进子文件夹」
> **口径**：**已实施**：三层日志（出口 / 分包 / 调试门控）落地，2026-10-23 实机验收通过（[§4.6](#46-决策表)）
> **范围**：1.7 `Source/KiiroSchizonepetaGum/Log/` 三个类与其调用点；不含日志落盘、外部上报、玩家可见开关界面
> **关联**：包类型来自 [02-发布流水线](02-发布流水线.md) 的双包产物；描边模块的调试日志见 [03-动画mod描边对齐.md](03-动画mod描边对齐.md)

## 4.1 诉求与现象

| 场景 | 现状 | 期望 |
|---|---|---|
| 玩家反馈问题时查 `Player.log` | 各模块直接调 `Log.Message` / `Log.Warning`，无统一前缀，无法判断是否本 mod | 所有输出经统一出口，前缀可检索 |
| 单 dll 承载多个功能模块 | 描边、核心的日志混在一起 | 按模块前缀分包（`Core` / `Outline`） |
| 调试信息刷屏 | 诊断日志在发行包里也输出，玩家日志被淹没 | 调试级只在调试包输出，发行包零开销 |
| 玩家反馈「你给的是哪个包」 | 无法从日志判断 | 启动日志打印包类型 |

## 4.2 机制

三层静态类，职责分离：

| 类 | 职责 |
|---|---|
| `KiiroGumLog` | 唯一出口：前缀翻译 + 着色 + `Msg`/`Warn`/`Err`/`Exception`/`Debug` |
| `KiiroGumLogModule` | 模块前缀常量（`Core`、`Outline`），新增模块只改这一处 |
| `KiiroGumDebug` | 编译期包类型 `DebugBuild` → `BuildTypeName` / `LogLevelName`；运行时开关 `EnableLog` |

输出格式为 `<color=#66CC33>[KiiroGum][模块]</color> 消息`：前缀取翻译 key
`KiiroGum.LogPrefix`，语言系统未就绪时回退硬编码 `[KiiroGum]`。

```csharp
// KiiroGumLog.cs L111-L118：Release 下调用点连同实参求值被整体移除
[Conditional("DEBUG")]
public static void Debug(string module, string msg)
{
    if (KiiroGumDebug.EnableLog)
    {
        Log.Message(Tag(module) + " [调试] " + msg);
    }
}
```

调试级用「编译期 + 运行时」双重门控：`[Conditional("DEBUG")]` 负责发行包零开销，
`KiiroGumDebug.EnableLog` 负责调试包内临时静默。包类型由编译配置自动驱动
（`#if DEBUG`），与 `Tools/Build-Release.ps1` 产出的 `Assemblies` / `AssembliesDebug`
一一对应，发版不需要手改常量。

## 4.3 现状排查

| 对象 | 结论 |
|---|---|
| 调用点 | `KiiroSchizonepetaGumMod`（启动信息）、`KiiroGumOutlineManager`（诊断 / 跳过 / 探针失败）、`KiiroGumOutlineGameComponent`（订阅渲染钩子） |
| 原 `OutlineConfig.DebugLogging` | 已删除：与编译期门控职责重复，且是玩家可见设置项 |
| 语言文件 | 中英 `Keyed/KiiroSchizonepetaGum.xml` 均已加 `KiiroGum.LogPrefix` |
| 文件组织 | 三个类在 `Log/` 子目录，命名空间仍为 `KiiroSchizonepetaGum`（SDK 风格工程自动包含子目录，无需改 csproj） |
| 已排除 | 日志落盘 / 分级过滤：RimWorld 统一写 `Player.log`，另建文件反而增加排错成本 |

## 4.4 候选做法

| 做法 | 落点 | 覆盖 | 副作用 | 结论 |
|---|---|---|---|---|
| 各模块直接调 `Log.*` | 各调用点 | 全模块 | 无前缀、无法检索、格式漂移 | 不实施 |
| 引入第三方日志库 | csproj | 全模块 | 新增程序集依赖，1.7 加载风险 | 不实施 |
| 自建三层静态封装（出口 / 分包 / 门控） | `Log/` 目录 | 全模块 | 需一次性迁移调用点 | ✅ 采用 |
| 用 mod 设置项控制调试日志 | 设置界面 | 全模块 | 玩家可见、发行包也编入调试字符串 | 不实施（改为编译期门控） |

## 4.5 影响面与副作用

| 维度 | 结论 |
|---|---|
| 兼容性 | 纯静态类，无 Harmony、无外部引用 |
| 依赖 | 无；前缀翻译缺失时自动回退 |
| 展示 | 前缀与启动口号用主题色 `#66CC33`；正文保留日志级别配色 |
| 翻译 | 新增 key `KiiroGum.LogPrefix`，中英各一条 |
| 性能 | 发行包调试调用点被编译移除，零开销；`Msg`/`Warn` 与直接调 `Log.*` 同级 |
| 回滚 | 删除 `Log/` 目录并恢复调用点即可，不影响功能逻辑 |
