## 2.1 诉求与现象

| 场景 | 现状 | 期望 |
|---|---|---|
| 版本标识 | `About.xml` 无 `<modVersion>`，工坊页面无法区分版本 | 版本号唯一可编辑点，zip/tag 由它派生 |
| 打包 | 手工压缩，易漏 `AssetBundles`、易把 `Source/` 带进包 | 一条命令产出干净包 |
| 双版本 | 1.6 与 1.7 各自有 dll，手工选择易错 | 一次运行产出全部版本，dll 按版本落位 |
| 排错 | 只有发行包，崩溃时无可对照的调试 dll | 有可编译工程时另出 Debug 包 |

## 2.2 机制

`Tools/Build-Release.ps1` 一次运行完成：读版本号 → 工作区/tag 告警（不阻塞）→ 按 `$BuildVersionDirs` 逐版本编译 Release+Debug → 白名单组装 `dist/stage/{release,debug}/<包名>/` → 校验关键文件 → 打 zip。

```powershell
powershell -ExecutionPolicy Bypass -File Tools\Build-Release.ps1                # 仅打包
powershell -ExecutionPolicy Bypass -File Tools\Build-Release.ps1 -CreateRelease # 打包并发 GitHub Release
```

| 约束 | 实现 |
|---|---|
| 版本号唯一人工编辑点 | `About/About.xml` 的 `<modVersion>`；Debug 包只在**包内副本**改写为 `<版本>-debug` |
| 开发目录不进包 | `robocopy /E /XD` 在**复制阶段**排除 `Source`/`AssembliesDebug`/`obj`/`bin`，避免与 IDE 抢 obj 句柄 |
| dll 正确性 | 由 csproj 的 `Assemblies` / `AssembliesDebug` 输出隔离保证，不靠编译顺序 |
| 包完整性 | 打包后校验 `LoadFolders.xml`、`About/About.xml`、`About/PublishedFileId.txt` 与各版本 `Assemblies/<dll>` |
| 脚本编码 | `Tools/*.ps1` 必须 UTF-8 **with BOM**（PowerShell 5.1 否则按 GBK 解码中文，报假语法错误） |

## 2.4 候选做法

| 做法 | 落点 | 覆盖 | 副作用 | 结论 |
|---|---|---|---|---|
| 本地 PowerShell 脚本 | `Tools/Build-Release.ps1` | 打包 + 可选 GitHub Release | 需本机有 dotnet/gh | ✅ 采用 |
| GitHub Actions | `.github/workflows/` | 全自动 | 需托管密钥、1.6 dll 不可重建 | 不实施（当前无收益） |
| 纯手工压缩 | — | 打包 | 易漏文件、无 Debug 包 | 不实施 |
| SteamCMD 上传工坊 | `Tools/Publish-Workshop.ps1` | 工坊发布 | 需 Steam 凭据与目录切换流程 | ⏳ 待拍板（§2.6 D8） |

## 2.5 影响面与副作用

| 维度 | 结论 |
|---|---|
| 兼容性 | 只影响发包，不改 mod 运行时行为 |
| 迁移 | 1.7 工程就绪后仅需 `$BuildVersionDirs = @('1.7')` 并加入 `$PackageVersionDirs` |
| 依赖 | 依赖 `dotnet`（本机 10.0.400-preview）与 `gh`（已登录）；`dotnet build` 需对应 TFM 的引用程序集 |
| 展示 | 玩家侧可见版本号从无到 `1.0.0` |
| 性能 | 无影响 |
| 回滚 | 删除 `Tools/` 与 `dist/` 即回到手工流程，仓库无副作用 |
